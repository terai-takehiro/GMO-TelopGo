# リモート連携 (2台運用) 設計・運用ガイド

## 概要

ローカルネットワークでつながった2台のPCで GMO TelopGo を運用するための機能。
同じアプリを両方のPCにインストールし、片方を**ホスト**、もう片方を**クライアント**として接続する。

```
┌─ ホストPC ────────────────┐     LAN      ┌─ クライアントPC ──────────┐
│ GMO TelopGo (ホストモード)   │◄─WebSocket─►│ GMO TelopGo (クライアント)  │
│  - 指定ポートで待受           │  状態同期     │  - ホストIP:ポートへ接続      │
│  - CONTEC DIO (GPIOボタン)  │  コマンド転送  │  - データ入力 / Excel / 送出 │
└─────────────────────────┘              └─────────────────────────┘
                                              │
                                              ▼ Singular Live API
                                     (「Singular送信担当」のPCから送信)
```

- どちらのPCでも **データ入力・Excel読込・並び替え・スケジュール/かるた操作・CHANGE/TAKE/CLEAR** が可能
- テロップデータと ON AIR / NEXT 状態は両PC間で**自動同期** (500ms間隔、最終書き込み優先)
- **接続時はホストのデータが正**となり、クライアントへ配布される

## セットアップ

### ホストPC (GPIOユニットのある側)

1. 設定タブ →「リモート連携 (2台運用)」
2. 動作モード: **ホスト** を選択
3. ポート番号: 任意 (既定 8765)
4. 「保存して開始」→ ステータスが「待受中」になる
5. **Windowsファイアウォールで指定ポートの受信を許可**する
   (初回起動時のダイアログで許可、または「詳細設定 → 受信の規則」でTCPポートを追加)

### クライアントPC

1. 動作モード: **クライアント** を選択
2. 接続先ホストIP: ホストPCのIPアドレス (例: `192.168.1.10`)
3. ポート番号: ホストと同じ値
4. 「保存して開始」→ ステータスが「接続中」になる

切断された場合は3秒間隔で自動再接続する。起動時は保存済み設定で自動的にリンクを開始する。

## Singular送信担当 (インターネット経路の選択)

Singular Live API の送信をどちらのPCが行うかを設定で選択する。
**インターネットに出られるPCを担当に指定**すること。

| 構成 | 担当の設定 |
|---|---|
| 両方インターネットに出られる | ホストPC (推奨) |
| ホストがオフライン・クライアントのみインターネットあり | **クライアントPC** |

担当でないPCで CHANGE / TAKE / CLEAR を操作した場合 (GPIOボタン含む)、
コマンドが担当PCへ転送されて実行され、結果のON AIR/NEXT状態が両PCに同期される。

例: ホストがオフラインの構成では、ホストPCのGPIOリモートボタンでTAKEを押すと
「ホスト → (LAN) → クライアント → (インターネット) → Singular Live」の経路で送出される。

この設定はホスト側の値が実効値として接続時にクライアントへ配布される。

## メッセージプロトコル

WebSocket (`ws://ホストIP:ポート`) 上のJSONメッセージ。

| type | 方向 | 内容 |
|---|---|---|
| `hello` | クライアント→ホスト | 接続通知 |
| `hello-ack` | ホスト→クライアント | 実効設定の配布 (`singularSide`) |
| `state-sync` | 双方向 | 全量スナップショット (データ + 送出状態)。ホストは他クライアントへ中継 |
| `command` | 双方向 | 送出コマンド `{action: change/take/clear, telopType: name/side}`。受信側は担当の場合のみ実行 |

### 状態同期の方式

- 500ms間隔で `{namePool, nameData, sideData, broadcast}` のスナップショットをJSON比較し、変化があればピアへ送信
- 受信側は入力欄の編集中でなければ即適用 (編集中はフォーカスが外れてから適用)
- 適用後のスナップショットを「送信済み」として記録し、エコーループを防止
- 同時編集は最終書き込み優先。2人のオペレーターが同じ行を同時に編集する運用は避けること

## 制約・注意事項

- **セキュリティ**: 認証なしの平文WebSocket。閉域のローカルネットワーク内でのみ使用すること
- **プレビュー**: 出力プレビュー(iframe)はインターネットから読み込むため、オフラインのPCでは表示されない (送出操作は問題なく可能)
- **GPIO**: CONTEC DIOユニットはホストPCに接続。クライアント側のGPIO設定は使用しない
- **プロジェクト保存/読込**: どちらのPCでも可能。読込むと同期により両PCに反映される
- **接続テスト** (Singular): 各PCが自分のインターネット経路でテストする (担当ルーティングは通らない)
